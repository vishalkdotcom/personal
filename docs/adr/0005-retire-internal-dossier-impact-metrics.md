# Retire Internal Dossier impact metrics

`InternalDossierCase` carried an optional `metrics` / `metricsFootnote` capability, deliberately scoped in the type comments as "Engage reporting only until a later Spec unlocks others." Engage Reporting was the only case that ever used it — Indicator Bank, Measurement Framework, Model Deployment Framework, and Store Dashboard all shipped without it. Beta feedback round 2 ([[10 — Rework Engage Reporting dossier outcomes]]) cut Engage's Tier A metrics row because it duplicates what's already on the CV — reasoning that generalizes to every Internal Dossier, not just Engage. We **retire the concept entirely**: remove `metrics` / `metricsFootnote` (and the now-unused `WorkImpactMetric` type) from `InternalDossierCase`, and drop the `WorkImpactMetrics` render branch in the stage. No Internal Dossier will carry an impact-metrics row. Rejected: leaving the optional fields in place as unused future capacity — an unused door just invites the same fog to resurface without a fresh rationale; a future dossier that genuinely needs a distinct proof beat gets its own Spec decision instead. Locked by Spec [[beta-feedback-round-2]] ([[12 — Decide impact-metrics scope for Internal Dossiers]]), superseding the original "for now" scoping in the inventory type comments.

# Vitest Browser Mode over JSDOM for App Shell tests

App Shell and theme preference seam tests previously ran under Vitest’s JSDOM environment with standalone `@testing-library/jest-dom` and simulated `fireEvent` interactions — a polyfill stack that diverges from how Modes, Triptych Dock, and theme preference actually run for visitors. We adopt **Vitest Browser Mode** with the **Playwright Chromium** provider only (`@vitest/browser-playwright`, pinned to `vitest`), split into Vitest `projects`: `browser` (`*.browser.test.ts(x)`) and `node` (`*.node.test.ts`). Solid components stay on **`@solidjs/testing-library`** bridged via `page.elementLocator` for locators and `expect.element` — rejected community **`vitest-browser-solid`** (validated against Solid 1.x, not this repo’s Solid 2 betas). The FOUC theme-boot script-before-stylesheet contract stays a cheap **Node** HTML structural guard, not a Browser Mode or paint-timing test. Dropped: `jsdom`, `@testing-library/jest-dom`. Local Chromium is an explicit `bun run test:install` (`playwright install chromium`); not on every `prepare` / `bun install`.
